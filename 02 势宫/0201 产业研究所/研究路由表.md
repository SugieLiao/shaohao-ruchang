## 一、为什么需要路由表

框架第七节定义了 Knowledge Workflow 的概念：

```text
News → Node Routing → 已有 Node？→ 更新 / 新建 → Finish
```

但概念不能直接执行。粟老师的 Agent 在实战中把它变成了一条硬规矩：

> "现在按 mysearch 规矩，先查路由表避免重复分诊，再确认一手源。"

区别在于：概念说"应该路由"，协议说"怎么路由"。这份文件把"应该"变成"怎么"。

### 2.1 Node 索引

每个 Node 登记以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|

### 2.2 关系索引

记录 Node 之间的连接，每条关系登记：

## 三、分诊协议

当新信息进入系统时，执行以下步骤：

```text
Step 1：提取实体
  从信息中提取产业关键词、公司名、产品名、技术名

Step 2：查路由表
  用提取的关键词匹配 Node 索引（名称 + 别名 + 关键词字段）

Step 3：分诊判定
  ├─ 命中单个 Node → 路由到该 Node，执行更新
  ├─ 命中多个 Node → 暂停执行，向宫主提交分诊报告：
  │    ① 建议路由到哪个 Node（主路由）
  │    ② 为什么选这个 Node（信息与该 Node 的关联度）
  │    ③ 为什么没选别的 Node（每个未选 Node 的排除理由）
  │    ④ 其他命中 Node 的关系更新建议（次要路由）
  │    → 获宫主批准后，执行 Step 4
  ├─ 部分命中（有相关 Node 但信息含新实体）→ 暂停执行，向宫主提交分诊报告：
  │    ① 建议更新哪个已有 Node（及其理由：信息与该 Node 的关联度）
  │    ② 建议新建什么最小 Node（及其理由：新实体无法归入任何已有 Node）
  │    ③ 为什么新实体不能并入已有 Node（排除理由）
  │    ④ 新旧 Node 之间的关系建立建议
  │    → 获宫主批准后，执行 Step 4
  └─ 完全未命中 → 新建最小 Node

Step 4：执行动作
  更新 → 更新 Node 内容、证据索引、必要时更新关系索引
  新建 → 创建最小 Node（名称 + 父节点 + 关键词 + 一条证据）

Step 5：记录路由决策
  在 Node 的更新日志中记录：什么信息、路由到哪、做了什么变更
```

### 分诊示例

**场景**：收到一条新闻"英伟达 8/14 宣布 Spectrum-X CPO 全面量产，公布供应链细节"

| 步骤 | 动作 | 结果 |
|------|------|------|
| Step 1 | 提取实体 | 英伟达、Spectrum-X、CPO、供应链 |
| Step 2 | 查路由表 | 匹配到 NODE-008（CPO）、NODE-010（Glass Bridge） |
| Step 3 | 分诊判定 | 命中多个 Node（NODE-008 CPO + NODE-010 Glass Bridge），暂停，提交分诊报告 |
| — | 分诊报告 | 建议主路由 NODE-008（CPO）：新闻核心是 Spectrum-X 全面量产，直接描述 CPO 量产状态。未选 NODE-010（Glass Bridge）作主路由：新闻未涉及 Glass Bridge 具体技术进展，但 Glass Bridge 是 CPO 的制造组件，建议关系更新。等待宫主批准。 |
| — | 宫主批准 | → 继续 Step 4 |
| Step 4 | 执行动作 | NODE-008 添加证据 EVD-022（8/14 推文，D 级），更新状态"CPO 已进入量产" |
| Step 5 | 记录决策 | NODE-008 日志：2026-08-17，路由来源=英伟达 8/14 推文，变更=量产状态确认 |

**场景二（部分命中）**：收到一条新闻"沃格光电 TGV 电镀填充工艺获新客户认证，天承科技 SOD 旋涂介电材料首次导入"

| 步骤 | 动作 | 结果 |
|------|------|------|
| Step 1 | 提取实体 | 沃格光电、TGV 电镀填充、天承科技、SOD 旋涂介电材料 |
| Step 2 | 查路由表 | 匹配到 NODE-010（Glass Bridge，关键词含 TGV）；天承科技 SOD 旋涂介电材料未命中任何 Node |
| Step 3 | 分诊判定 | 部分命中（NODE-010 相关 + 新实体 SOD 旋涂介电材料），暂停，提交分诊报告 |
| — | 分诊报告 | 建议更新 NODE-010（Glass Bridge）：沃格光电 TGV 电镀填充获认证是其制造链的直接进展。建议新建最小 Node「SOD 旋涂介电材料」：SOD 是 HBM 堆叠间绝缘的关键材料，无法归入 Glass Bridge Node（不属于玻璃基板封装，属于存储封装材料体系）。排除理由：SOD 不能并入 NODE-010 是因为材料体系不同、应用环节不同（存储 vs 封装基板）。关系建议：新 Node「SOD 旋涂介电材料」与 NODE-006（存储产业）建立"属于"关系。等待宫主批准。 |
| — | 宫主批准 | → 继续 Step 4 |
| Step 4 | 执行动作 | NODE-010 添加证据 EVD-023（沃格认证，D 级）；新建 NODE-011（SOD 旋涂介电材料），关键词：SOD/旋涂/介电/HBM 绝缘，父节点：NODE-006，一条证据 EVD-024（天承科技导入，D 级） |
| Step 5 | 记录决策 | NODE-010 日志：TGV 电镀填充认证更新；NODE-011 日志：新建，路由来源=天承科技新闻 |

## 四、去重规则

### 4.1 事实去重

同一事实只登记一次。后续出现相同事实的不同来源报道，更新同一条证据的来源列表，不新建证据条目。

```text
首次："沃格光电 5μm 孔径 TGV"（财通证券 6/24，B 级）→ EVD-015
再次："沃格光电 TGV 微孔精度领先"（科创板日报 6/25，D 级）→ 更新 EVD-015 来源，不新建
```

### 4.2 结论去重

同一研究结论在不同 Node 下不重复展开。如果结论跨 Node，在主 Node 下展开，在其他 Node 下只放引用。

```text
"原片占基板成本 60-70%" 这个结论
→ 在 NODE-005（玻璃原片）下展开
→ 在 NODE-001（TGV）下只写：见 NODE-005，利润集中度
```

### 4.3 证据升级

同一事实获得更高等级信源时，升级证据等级，保留原始来源。

```text
EVD-020：原片占成本 60-70%
  原始：E 级（自媒体）
  升级：B 级（财通证券交叉验证）
  状态：updated，等级 B
```

## 五、与框架的关系

| 框架要素 | 路由表对应的执行 |
|------|------|
| 第三节 Node 是最小研究单位 | Node 索引是所有 Node 的注册表 |
| 第四节 节点关系（六问） | 关系索引是六问的结构化存储 |
| 第七节 Knowledge Workflow | 分诊协议是 Node Routing 的执行步骤 |
| 第五节 Evidence（九问） | 证据索引是信源分级的落地存储 |
| 框架暗线 6（研究路由表） | 本文件即为该暗线的独立成文 |

路由表不替代框架正文，而是框架的**执行层**——框架定义"研究什么"，路由表定义"信息怎么进系统、怎么找到归属"。

## 六、最小充分设计声明

本协议按"最小充分设计"原则编写，只定义当前能预见到的执行规则。以下问题留给第一个真实 Node 研究验证后决定：

- 关键词匹配用人工判断还是需要自动化匹配工具
- Node ID 编号体系是否需要按产业分类加前缀（如 SEMI-001 / OPTO-001）
- 关系索引的六种关系类型是否足够覆盖实际场景
- 证据去重时"同一事实"的判定边界（相似到什么程度算重复）
- 路由表是否需要独立为数据库/结构化文件，还是维持 Markdown 表格

这些问题不在现在提前设计，等第一个真实 Node 跑完后再根据实际痛点迭代。

## 七、操作清单（首个 Node 研究时使用）

1. 建立第一个 Node 条目（Node 索引）
2. 收集信息时逐条执行分诊协议
3. 每条信息登记为证据（证据索引）
4. 发现新 Node 时建立关系（关系索引）
5. 研究完成后记录"路由表哪里不顺手"
6. 根据反馈迭代本协议

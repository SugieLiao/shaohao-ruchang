# Builder Workflow

## 1. 受命

- 阅读 Issue、Blueprint 与仓库约定。
- 明确范围、交付物和验收条件。
- 确认工作区中已有变更的归属。

## 2. 开工

- 从目标基线创建独立分支。
- 按 Blueprint 建立或调整结构。
- 只修改本 Issue 所需的内容。

## 3. 自检

- 核对目录、文件名和链接。
- 检查 `git diff`，排除无关变更。
- 执行与变更相称的验证。
- 更新 `10 营造司/营造志/CHANGELOG.md`。

## 4. 交付

- 使用清晰、单一目的的提交信息。
- 推送独立分支。
- 创建 Draft Pull Request，并说明变更、原因和验证结果。

## 5. 守候

- 不自行 Merge。
- 等待 Review，逐项处理反馈。
- 获得批准后再由有权限的角色决定合并。
